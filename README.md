# Magic Video · 本地播放历史与断点续播工具

> 一个只跑在你自己电脑上的追番/看剧记录工具。**外观是独立软件窗口，数据全部留在本机。**
> 当前版本：**v0.1.7**（语义化版本，唯一真源为 `app/__init__.py` 的 `__version__`）

## 2. 快速开始

### 安装（一次性）

```bat
cd /d "D:\project\magic video"
python -m pip install -r requirements.txt
```

依赖仅 6 个：`pywebview`、`pythonnet`、`pystray`、`Pillow`、`requests`、`psutil`。
本机已实测安装完成（Python 3.13 / Node 22 / SQLite 3.53 / Edge WebView2 157）。

### 打包产物（目标机器无需 Python）

由 `build_dist.py` 一键生成：

```bat
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt pyinstaller
.venv\Scripts\python.exe build_dist.py
```

| 产物 | 位置 | 播放记录存哪 |
|---|---|---|
| 绿色版 ZIP | `dist/MagicVideo-<版本>-win64-portable.zip` | 解压目录内 `Magic Video/data/`（靠 `portable.txt` 标记） |
| MSI 安装版 | `dist/MagicVideo-<版本>-win64.msi` | `D:\magicvideo`（默认，可用 `MAGIC_VIDEO_DATA_DIR` 覆盖） |

- 绿色版解压即用；删掉 `portable.txt` 就切换到「安装版」的数据位置。MSI 为 **perUser 安装**（`%LOCALAPPDATA%\Programs\Magic Video`），双击即可安装、不需要管理员，带开始菜单快捷方式与卸载入口。
- 两种形态都只有 `Magic Video.exe` 一个可执行文件：主窗口、托盘守护（`--daemon`）、构建自检（`--selftest`）复用它；开机自启和托盘菜单会自动选择源码版或打包版的启动命令。
- **资源与数据分离**：网页、内置词典、文档随程序分发（只读），数据库单独放用户可写目录，升级或重装不会丢播放记录。可用环境变量 `MAGIC_VIDEO_DATA_DIR` 显式指定数据目录。
- 首次构建需联网下载 WiX 3.14 工具包（约 40 MB，落在 `build/tools/`），`build/` 与 `dist/` 均不入库。
- **升级安装**：直接双击新版 MSI 即可自动替换旧版；数据库在 `D:\magicvideo`（不在安装目录），播放记录完整保留。新版已关闭 WebView2 持久缓存并给 `app.js` 加版本串，避免升级后仍显示旧界面。
- **安装路径会被记住**：安装向导里的目标是默认的 `%LOCALAPPDATA%\Programs\Magic Video`，可以改成任意目录（例如 `D:\Apps\Magic Video`）；装好后实际路径写进 `HKCU\Software\Magic Video\InstallPath`，下次升级自动装回同一位置，不用每次重选。**旧版本（0.1.5 之前）没有记这个值**，所以第一次升级仍落到默认目录，之后开始生效。
- **「应用和功能」里的安装位置**会显示真实目录（`ARPINSTALLLOCATION` 由安装包写入），不再是空白。
- **数据目录默认值**：源码版与打包版统一为 `D:\magicvideo`（`app/config.py::DEFAULT_DATA_DIR`），守护进程与开机自启也走同一默认值；`./start` 会显式 export 同一路径以便守护继承。旧 `%APPDATA%\Magic Video` 目录保留未删除，可随时回滚。

### 启动

| 操作 | 效果 |
|---|---|
| **`./start`（Git Bash，项目根目录）** | **推荐**：一键从源码打开主窗口，直接连**真实数据库**（`D:\magicvideo\library.db`） |
| `./start --local` | 改用项目内 `data/library.db` 的调试库，不碰真实记录 |
| `./start --debug` | 附带打开 DevTools |
| 双击 `dev.bat` | 调试入口：默认复制真实库成 `data/dev/library.db` 安全副本后启动；`dev.bat --real` 直接连真实库 |
| 双击 `start.bat` | 打开主界面（9 个功能页） |
| 双击 `start_daemon.bat` | 手动单独启动托盘常驻记录（无控制台窗口）；平时**不需要**用它 |
| 「设置」页 →「启动软件时自动开启后台记录」 | **默认开启**：打开主窗口即自动拉起托盘守护；关闭时立即停掉当前守护，再打开可立刻补拉起 |
| 「设置」页 →「开机自动启动后台记录」 | 写 `HKCU\...\CurrentVersion\Run`，无需管理员权限；与上一条互不影响 |

> **两个开关不一样**：`daemon_auto_start` 管「每次打开本软件时拉起守护」（默认开），`autostart` 管「登录 Windows 时自启」（默认关），`recording_enabled` 管「守护是否写历史」。三者互不覆盖。

> **数据库在哪**：`./start` / `start.bat` / 安装版默认用的是
> `D:\magicvideo\library.db`（D 盘，用户指定）。`./start` 启动时会把数据目录和 `.db` 完整路径打印出来。
> 绿色版若带 `portable.txt` 仍写解压目录下的 `data/`。
> 只有 `./start --local`、`dev.bat` 默认模式、`data/dev/` 才是调试副本；调试副本里导入/播放不会写进真实记录。
> 封面在 `<数据目录>\covers\`，日志在 `<数据目录>\logs\`，全部**只在本机**。
> 重复点任务栏图标不会再开第二个窗口：互斥锁检测到已有实例后只把旧窗口置前。

### 三步用起来

1. **导入列表** → 粘贴作品名，点「解析预览并匹配中文名」→ 中文名当场出现且可手改 → 点「确认导入」。
2. **添加视频目录** → 填入已下载视频所在文件夹 → 自动递归扫描，外文文件名当场转成中文名。
3. **继续观看** → 从列表点开任意一集，PotPlayer 以 `/seek=hh:mm:ss` 从上次位置启动；播放过程自动写入进度与会话。

> 即使不通过本工具、直接双击用 PotPlayer 打开视频，托盘守护也会记录（会用窗口标题建一条 `external` 占位记录）。
> 把该视频所在目录加进「扫描目录」后，续播即可正常使用。

### 媒体库树状视图（0.1.5 迭代）

平铺列表把 2104 个文件一次铺开，很难看出「哪几集属于同一部、哪一季」。工具栏的**展示方式**可切换三种视图，搜索、目录筛选、匹配状态筛选在三种视图里都生效：

| 视图 | 层级 | 适用 |
|---|---|---|
| 作品 → 季 → 集（媒体库默认） | 作品 → 第 1 季 / 第 2 季 / 第 3 季 / 未标注季 → 每一集 | 追剧、追番；第一季第二季分别成组，十几集展开即可看到 |

### 启动体验、剧集墙、快搜与软件内播放（0.1.5 迭代）

这一批是按实际使用反馈补的，开发期间**不单独打包、不打 tag**，随 `v0.1.5` 一次性发布。

**启动与单实例**

- `app/single_instance.py` 用命名互斥锁保证只有一个主窗口；第二个进程只把已有窗口 `ShowWindow(SW_RESTORE)` + 置前，不再初始化第二个 WebView2（这正是之前启动卡顿和多窗口的来源）。
- `js_api` 只以 `_window` 私有属性持有 pywebview Window，避免 `dir()` 深度反射 .NET 控件树时刷 `CoreWebView2` 的 `E_NOINTERFACE` 报错；`webview.start(gui="edgechromium", private_mode=True)` 不再传 `background_color`。
- 读播放器状态改用 `SendMessageTimeoutW(..., SMTO_ABORTIFHUNG, 300ms)`，PotPlayer 忙时不会把 3 秒一次的界面轮询挂死。
- 设置存在 SQLite，窗口关闭后主题、窗口尺寸、开关都还在。
- **后台记录默认自动启动**：`app/main.py` 建好窗口后调用 `Api.ensure_daemon_auto_start()`，前端 `init()` 再做一次幂等兜底；已在运行或设置里关掉都不会重复拉起。左下角与「总览」的手动启动按钮已移除，只保留状态圆点。设置页关闭时会调用 `stop_daemon()` 立即停掉守护，重新打开则马上补拉起。`Api.__init__` 绝不启动进程，避免单测拉起真实守护。

**剧集墙与封面**

- 「剧集墙」参考 SeedHub / AGE动漫 做卡片式作品墙：封面、季数、集数、已看/在看。卡片**不再有「播放下一集」**；「查看分集」会带一个干净的中文搜索词跳到媒体库并自动展开命中分组，脏分组名（如把 `[1.36G]` 当标题）会退回文件名括号里的真实片名。
- 封面抓取的入口与进度**已整体迁到「后台进程」页**，剧集墙不再显示任何抓取控件；仍然只在用户点按钮时启动**一次性**后台线程（不是定时任务、不开机自跑）。
- **用官方搜索 URL 抓「对」的图**（2026-11-15 修正）：主源 `agedm.io/search?query=<关键词>`、备源 `seeduck.cc/s/<关键词>/`，都按关键词搜。
  AGE 结果块只取 `data-original` 的真实封面（并从百度图片代理的 `src=` 参数解出原始 CDN 直连），
  **彻底排除所有结果共用的占位 `src`**；切块改用字符串末尾兜底，保证最后一块（常是精确匹配）不丢；
  Seeduck 搜索页用 `<h2>` 干净短标题配对，不再靠固定首页池凑数。
  匹配按「标题精确 → 去季精确 → 严格相似度（0.90 且只允许季/续作后缀）」，**宁可返回未找到也不拿别的作品的图**。
- **人工设定封面**：剧集墙 / 看过的列表卡片墙的「设定封面」按钮，支持 **Ctrl+V 粘贴剪贴板图片**、
  选本地图片文件、或粘贴图片网址；三种来源都由后端校验魔数与 3 MB 上限后落盘。
  人工封面写 `subjects(source='manual')`，`resolve_cover()` 优先命中，**连「强制重抓」也不会覆盖**；
  弹窗里的「恢复自动」才撤销。实测 5 个常用中文标题全部精确命中且各为真实 JPEG（24~58 KB）。
- **不再用完整长标题去搜站点**：`app/textmatch.py::query_variants()` 把标题拆成《书名号》内容、去季/集标记的主标题、最长中文片段与英文关键词，按可信度逐个尝试。
- HTTPS 代理偶发断连会重试，非 200 快速换源，单次任务有总预算防卡死。
- 图片通过 `cover_data_uris()` 转成 data URI 给 WebView2 显示（不依赖 `file://` 权限）；下载到 `<数据目录>\covers\`，`cover_url` / `cover_local` 写进 `subjects`，已有封面直接命中缓存不重复下载。
- 抓取顺序优先「剧集墙卡片标题」（与媒体库树同一套分组），其次导入清单中文名；`cover_key()` 去掉季标记与尾集号，同一部番逐集分组只抓一张共用封面。脏英文文件名、番号编号与「（完）」残行会被过滤。

**全盘快搜（Everything）**

- 左侧导航里的**独立入口**，不再挂在「剧集墙」下面；页面顶部显示当前检索通道，也可一键跳到「设置」配置。
- 优先调 `es.exe`，其次 Everything 的 HTTP 服务（支持 Basic Auth 用户名/密码）；两者都没配置时**自动降级**为媒体库内检索，所以功能始终可用。
- **Everything 核心引擎闭源，无法编译进本软件**：GitHub 上 `voidtools/ES` 是 MIT 许可的命令行客户端 / SDK，只是连到正在运行的 Everything 实例的 IPC 客户端；Lite 版还会禁用 IPC/ES/HTTP，必须用完整版。
- 官方 `es.exe`（`ES-1.1.0.38.x64.zip`）已下载到 `D:\tool\Everything\es.exe`。但本机 Everything 1.4.1.1032 以 `-svc`（会话 0 服务）运行，用户会话的 es.exe 连不上 IPC（Error 8）——这是会话隔离，不是没装。
  软件现在会**明确提示改走 HTTP**：在 Everything「选项 → HTTP 服务器」启用并设端口（如 8080），到「设置 → 全盘快搜」填 `http://127.0.0.1:8080` 即可全盘检索。
- 快搜页 / 设置页都有「打开 Everything」快捷按钮，路径由后端固定配置决定（前端不传参，`os.startfile` 打开），主程序不存在时按钮置灰。
- 搜索结果里不在扫描库的文件也能直接播放，守护进程会留一条 `external` 记录。

**PotPlayer 软件内播放**

- 默认开启。点任意「播放 / 续播 / 从头播放」或快搜结果里的播放时，界面先展开「播放舞台」，再由 `app/embedded_player.py` 用纯 Win32 `SetParent` + `SetWindowPos` 把 PotPlayer 窗口嵌到主窗口里、按 `#playerHost` 的屏幕矩形（CSS 像素 × DPR）摆位。
- **全程不碰 `window.native`**：按 PID + 标题枚举主窗口 HWND，绕开非 UI 线程访问 WebView2 COM 控件会抛 `E_NOINTERFACE` 的问题。
- **失败即降级**：找不到主窗口、等不到 PotPlayer 窗口、`SetParent` / `SetWindowPos` 失败、非 Windows 平台，都会让 PotPlayer 照常在独立窗口播放，并提示降级原因，绝不会出现「点了没反应」。
- 内嵌后播放器不再是顶层窗口，`FindWindowW` 找不到它；因此把 HWND 写进 `settings.embed_hwnd`，**另一个进程**的托盘守护也能继续读进度、写会话。关闭主窗口或点「退出内嵌播放」都会把窗口还原成独立顶层窗口，不会留下孤儿子窗口。
- 右上角「内嵌播放」开关、设置页「在软件内播放 PotPlayer」两处都可关掉，改回原来的独立窗口播放。

**播放控制条（0.1.5 迭代）**

- **PotPlayer 是 Kakao/Daum 的闭源专有软件，官方从未公开源码，GitHub 上没有可集成的播放器本体**；因此没有「下载源码集成」这一步，改为在本软件里做一层完整的控制 UI：播放舞台底部独立控制条（HTML 层，不会被 `SetParent` 进来的原生子窗口盖住），**播放/暂停与停止居中**，两侧是上一集 / 下一集与倍速下拉，全屏按钮固定在**右下角**。
- 运行时控制靠 `app/potplayer.py` 新增的按键通道：`PostMessage(WM_KEYDOWN/WM_KEYUP)` 直接投到播放器 HWND（内嵌时窗口是 `WS_CHILD`、没有键盘焦点，不能用只作用于前台线程的 `SendInput`）。动作走白名单，键位与倍速步进全部可在「设置 → 播放控制键位」里改，换 PotPlayer 版本或自定义过快捷键也不会整套失效。
- **倍速**：PotPlayer 倍速键是步进式的，没有直接设 1.25× 的接口。每次先把倍速复位到 1.0，再按 N 次加速键，结果与当前倍速无关；步进 0.1 时 1.25× 不可精确到达，界面会如实提示实际值（1.2×），把步进改成 0.25 后 1.25 / 1.5 / 2.0 全部精确可达。
- **上一集 / 下一集**：`Api.player_adjacent()` 复用媒体库同一套「作品 → 季 → 集」分组与排序找相邻集，再走现有 `playSmart` 换片，播放记录与断点照常写入；跨季按整体顺序连续跳转，第一集/最后一集会明确提示。
- **全屏**：内嵌模式下 PotPlayer 是子窗口，触发它自身全屏会脱离父窗口并破坏布局，所以按钮改为把播放区**放大到整个软件窗口**（隐藏标题条、保留控制条并重新摆位）；只有独立窗口模式才把全屏键发给播放器。

### 展示视图、分组修正与作品改名（0.1.5 迭代）

**四种文件视图**（`扫描目录` 与 `媒体库` 共用同一套工具栏、搜索与筛选）：

| 视图 | 内容 | 默认 |
|---|---|---|
| 封面墙 `cards` | 每部作品一张封面卡片 + 一个作品名，点「查看分集」带搜索词跳到媒体库 | 媒体库 |
| 剧集展示 `series` | 作品 → 季 → 集；有季标记才分季，无季文件直接挂在作品组下 | 从剧集墙跳过来时 |
| 目录结构 `folder` | 扫描根目录 → 子目录 → 文件，目录名即磁盘真实文件夹 | 扫描目录 |
| 平铺列表 `flat` | 全量文件逐行、可翻页或一次显示全部 | 手动切换 |

- 「看过的列表」另有**卡片墙 / 表格**两视图：默认**平铺表格**（一行一条、不按作品折叠、去掉中文名列），可一键切到卡片墙（一部作品一张封面、只显示一个作品名）；双击作品名仍可改名，已匹配的中文名通过隐藏域原样保留，导入原文与搜索能力不变。
- **历史按作品去重**：`get_history()` 以作品标题（中文名 > 推断名）为分组键，同一部剧的不同集只显示**最新一次**会话；无标题的会话按 `file_id` / `-id` 独立保留。只收拢展示，`watch_sessions` 旧会话一条不删。真实库 19 条会话收敛为 4 条，「更衣人偶坠入爱河」9 条 → 1 条（人工删除最新一条后自动露出该作品次新一条）。
- 封面一律走 `cover_data_uris()` 读本地缓存转 data URI，**不触发后台抓取任务**；想补封面请到左侧「后台进程」页手动点开始。
- **分组修正**：`Anna.Directors.Cut.E01…E08` 现在按发布目录归并成一部剧且集号 1–8 可读（`parse_filename` 支持无 S 前缀的 `E01`）；`WWW.17BT.CN@爱的躯壳[…][1.36G]` 不再把体积当作品名，显示为「爱的躯壳」。目录名改为逐段去噪，避免中文片名被 `17bt` / `BTHDTV` 等站点标记连坐丢掉；最内层目录全是噪音时继续向外找。
- **作品改名**：剧集树节点与封面卡片上都有「改名」按钮，填新名后写进 `settings.work_labels_json` 映射（按分组 id 索引），媒体库树、剧集墙、整剧看完校验三处同源生效；留空即恢复自动识别的名称。改名**只改展示标签**，不 `UPDATE media_files`、不动播放记录、不改磁盘文件。
- **看过的列表 → 打开文件夹**：`Api.watched_folders()` 复用 `watchlist.media_index()` + `match_files()` 按作品名 / 中文名匹配本地文件，取命中文件最多的**发布目录**（不是扫描根目录）返回给前端，匹配到的条目才出现「打开文件夹」按钮。点击时 `Api.open_watched_folder(id)` **按 id 重新计算**并做二次校验（绝对路径 / 真实存在 / 不在系统目录黑名单 / 落在 `directories` 登记的扫描根内），再用 `os.startfile` 打开。前端**只传 id、不传路径**，不拼接任何 shell 命令；目录接口异常时只隐藏按钮，列表照常可用。发布目录若已被移走/改名，`Api._existing_folder()` 最多向上退 2 层找仍存在、仍在扫描根内的一级作品目录，且**不会退到扫描根本身或跨出扫描根**。真实库只读实测 134 条中 **8 条**能匹配到目录，其余作品本地确实没有对应文件（关键词在媒体库中命中数为 0），属于预期而非漏配；全量匹配一次约 0.16s。
  - **「从播放记录同步」的大量条目**：同步按集写入，一整部剧会生成几十条同名行，且 `title_cn` 会回退成 `title`。`watched_folders()` 整批只建一次媒体索引、`title == title_cn` 只匹配一次、一次调用内按 `(title, title_cn)` 复用结果（缓存只在本次调用内，数据变更下次自然重算，不会有陈旧按钮）。隔离库模拟 **3000 条同步记录 / 100 部作品 / 600 个媒体文件，匹配 0.09s**。同步完成后前端会重新取目录映射，新条目的按钮当场出现。

### 追剧列表与后台进程管理（0.1.5 迭代）

**追剧列表**：左侧独立入口，分「已下载 / 未下载」两栏。导入时按你书写的顺序写入 `watchlist.sort_order`，分栏由 `已下载：` / `未下载：` 两行决定；重复标题幂等去重。

- ↑↓ 按钮逐条调整顺序，**⇈ 一键置顶**（只改这一条所在栏的 `sort_order`，一下移到该栏最上面，不重排其它行、不跨栏）；两栏之间一键互转、行内改名与增删，所有操作都只改 `sort_order` / `downloaded`。
- 操作按钮统一 24px 高度、↑↓⇈ 等宽图标位、整组右对齐并在窄窗口自动换行，不再出现按钮高低不齐或挤成一团。
- 每一条都会用 `query_variants()` 生成的短关键词去 `media_files` 里找本地剧集（按关键词优先级逐个尝试，首个命中即停，短英文词按独立单词匹配，避免 `Zero` 命中上百个文件）。
- 命中的条目可以**就地展开**列出文件并直接点播，也可以点「媒体库搜索」带标题跳过去；未命中的条目保持原样，不影响播放记录。
- `watchlist` 与 `media_files` / `watch_progress` **没有外键**：删一条追剧记录绝不会动到任何观看进度或历史。

**后台进程**：左侧独立标签，把原来分散在剧集墙的封面控件全部收进来。

- 上半区显示托盘守护的运行状态与 PID，可「启动 / 停止」；下半区是封面缓存任务：开始 / 强制重抓 / 停止，进度条、当前正在搜的关键词、AGE动漫 / SeedHub 各源命中数、最近失败原因。
- 进度轮询**只在停留于该页面期间**存在，切走即停；抓取本身仍然是一次性用户触发任务，没有开机自跑或定时调度。

### 同步去重、视频黑名单、播放条常驻与媒体库切换优化（0.1.5 迭代）

**从播放记录同步不再刷重复行**。「看过的列表 → 从播放记录同步」以前对每个已看完文件插一行，而判重键含集号，所以一部 12 集番会变成 12 条记录。现在：

- 先按 `(作品名, 季)` 聚合成**一条区间行**（`episode_from` 取最小集号、`episode_to` 取最大集号），再与既有行取并集：整部行（区间为 NULL）覆盖一切，部分重叠则扩展区间，**同作品同季始终只有一行**。
- 点一次同步会顺带把历史遗留的 `source='playback'` 重复行合并掉（`match_by='user'` 的手改行优先保留），结果里会显示「扩展 N 条 / 合并 N 条旧重复」。
- 只处理 `source='playback'`；手动导入行、其它来源、播放进度与观看会话一律不动。

**视频黑名单（设置页，默认开启）**。名称包含任一关键词的视频在所有展示位置默认隐藏，关键词以逗号 / 顿号 / 分号 / 换行分隔，**不区分大小写**：

- 覆盖媒体库（平铺 / 剧集展示 / 目录结构 / 封面墙）、扫描结果、看过的列表、播放历史、继续观看、追剧列表的「本地 N 个文件」匹配与全盘快搜结果；总览统计数字同步扣除。
- 只是**展示层过滤**：不删 `media_files`、不删播放记录、不删追剧清单条目；关掉「启用黑名单过滤」后所有位置立刻恢复展示全部视频。
- 匹配口径就是「名称包含」（用户明确要求），因此 `jul` / `ipx` / `ure` 这类短词可能误伤正常片名，从词表里删掉即可；`path` 不参与判定，避免目录名连带隐藏整棵子树。

**播放控制条常驻顶栏**。以前控制条只存在于内嵌播放舞台里，用独立窗口播放时完全看不到倍速和上下集。现在顶栏右侧有常驻控制条（上一集 / 播放暂停 / 停止 / 下一集 / 倍速 / 全屏），PotPlayer 在运行或已有当前条目时自动出现；软件重启后若播放器仍在播，会按状态里的 `file_id` 补上「当前条目」，上下集立即可用。独立窗口模式下「全屏」按钮也会把全屏键投给播放器，不再点了没反应。

**媒体库切换更跟手**：

- 点「媒体库」立刻出骨架画面，再做「查目录 → 全库分组 → 封面转换」，不再白屏等三步串行返回；目录列表 8 秒内复用。
- 封面 data URI 两层缓存：后端按文件 `mtime + size` 缓存编码结果，前端 `coverUriCache` 只请求缺的标题；人工设定 / 恢复自动封面后自动失效。
- 封面墙改成两段式渲染：先画出整面占位卡片，封面到位再补一次，不再等几百张 base64 全部转换完才首次渲染。

**看过的列表卡片墙可正常下拉**。`content-fill` 的 `flex: none` 规则把 `.watched-cards` 也一起冻结，高度塌陷后内容被 `overflow: hidden` 裁掉。已给卡片墙单独声明 `flex: 1 1 auto; min-height: 0; overflow: auto`，卡片墙内部滚动，表格视图与设置页 sticky 不受影响。

### 播放指令通道、媒体库提速、卡片墙结构、黑名单归一化与网页搜索（0.1.5 迭代）

**播放按钮改用 PotPlayer 官方菜单指令**。之前顶栏「播放暂停 / 停止 / 倍速」全是把快捷键投到播放器窗口，遇到自定义键位、内嵌成子窗口、播放器不在前台时会**静默失败**，表现就是「点了没反应」。现在：

- 播放类动作走 PotPlayer 的 `WM_COMMAND` 菜单命令号（播放暂停 `10014`、停止 `20002`），不依赖窗口焦点，也不受键位设置影响。
- 每条尝试都用 `WM_USER 0x5006` 读回播放状态**复查是否真的生效**，没生效才依次退到 `POT_SET_PLAY_STATUS`（`0x5007`）与快捷键；三条都不行时如实报错，不再假装成功。
- 三条通道**按需逐条发出**，不会一次全发（否则暂停+切换+空格会连切三次，画面看起来毫无变化）。
- 倍速与全屏走 `POT_SEND_VIRTUAL_KEY`（`0x5010`）虚拟键通道，同样不需要焦点；老版本不认时退回 `WM_KEYDOWN`。

**媒体库与剧集墙明显变快**（实测 2100 个文件 / 195 部作品）：

| 场景 | 改前 | 改后（首次） | 改后（再次切回） |
|---|---|---|---|
| 打开剧集墙 | 1105 ms | 257 ms | 7 ms |
| 打开媒体库（剧集展示） | 511 ms | 177 ms | 6 ms |

三处根因：① `_is_tech_token` 每次调用都重新编译正则（8 万次编译占了一半耗时）→ 改成预编译 + 目录名解析加缓存；② 剧集墙逐张解析封面时反复重建 subjects 索引并逐个 `stat()` → 改成索引建一次、批量解析；③ Python 侧每判断一个分组标题都开一次 SQLite 连接读设置（每次连接还重设一遍 WAL）→ 改成 WAL 只在首次设一次、黑名单词表按「库路径 + 写库次数」缓存。结果按「选项 + 数据指纹」缓存，写库（扫描 / 改名 / 改设置）自动失效，不会看到旧数据。

**看过的列表卡片墙改成与剧集墙同一套结构**。整面墙由「外层普通块 + 内层 `.poster-grid`」组成，卡片模式不再套 `content-fill`（改走整页滚动）。之前 grid 既当 flex 子项又被 `overflow: hidden` 裁剪，卡片被压成一条、标题也被挤没了。

**黑名单能命中带连接符的名称了**。用户词表里写 `FC2PPV`，真实文件名是 `FC2-PPV-1288053`、`mvsd.naiad`、`SSIS_001` —— 只做「原样包含」会整片漏掉。现在两侧都去掉 `- _ . · 空格` 再比；另外**目录名派生的作品名**（文件名里根本没有关键词）也会在剧集墙卡片与媒体库分组这一层再筛一遍，这就是「剧集墙还能看到黑名单剧集」的两个真因。

**新增「网页搜索」左侧入口**。同时抓 `agedm.io/search?query=` 与 `seeduck.cc/s/<关键词>/` 的搜索结果，渲染成封面卡片并**标明来源**；点「打开网页」用系统默认浏览器打开详情页。任一站点不通或改版只影响它自己的结果，失败方会显示原因并保留「去站点搜索」按钮。链接打开走白名单：只放行 `http/https`，`file:` / `javascript:` 之类一律拒绝。


### 人工清理：删记录 / 删文件，观看记录不自动消失（0.1.5 迭代）

**软件永远不会自动删除任何观看记录。** 只有你在界面上点按钮、并在二次确认框里确认，才会发生以下两件事之一：

| 想做什么 | 去哪里 | 实际发生什么 |
|---|---|---|
| 删掉某次观看会话 | 「历史记录」每行「删除」 | 只删 `watch_sessions` 里这一行；本地文件、`watch_progress` 断点、`watched_list` 全部保留 |
| 删掉已看完的某一集文件 | 「继续观看 → 已看完」或「媒体库」文件行的「删除本地文件 / 删除文件」 | 单个视频移入 **Windows 回收站**（可恢复），并给 `media_files` 打 `deleted_at` 标记 |
| 删掉整部已看完剧集的本地文件 | 「剧集墙」卡片的「清理本地文件」，或「媒体库 → 剧集展示」作品节点的「删除整部本地文件」 | 后端重新校验**该作品每一集都是 `completed=1`**，再逐个移入回收站 |

- 二次确认框会列出**全部待删文件的完整路径**、合计大小与明确的危险警告，默认焦点在「取消」，Esc / 点遮罩都算取消。
- 删除前先由后端 `get_delete_candidates()` 生成权威清单；真正执行时 `delete_local_files()` 会**再次**独立校验"已看完 / 属于该作品 / 路径是受支持的视频文件 / 不在系统目录 / 未被删过"，任一不满足就跳过或整体拒绝。
- 用 `SHFileOperationW(FO_DELETE + FOF_ALLOWUNDO)` 移入回收站；接口失败只报错，**绝不降级为永久删除**（`app/file_ops.py` 里没有 `os.remove` / `unlink` / `rmtree`）。单次上限 300 个文件。
- **数据库零 DELETE**：`watch_progress` 和 `watch_sessions` 对 `media_files` 是 `ON DELETE CASCADE` 外键，所以删文件只 `UPDATE media_files.deleted_at`，绝不删行；进度、断点、观看会话、看过的列表、媒体库条目全部保留。界面会把这些文件标成「本地文件已移除」。
- 从回收站恢复文件后再扫描一次目录，`deleted_at` 标记会自动清掉；就算不恢复，扫描发现文件消失也**只跳过、不删记录**。
- 没有任何定时/后台清理任务：删除入口只在用户点击时存在。

### 中文名匹配机制（重要）

**只在三个动作里同步执行，没有任何定时任务、后台回填队列或待办文件：**

```
导入列表预览 / 扫描目录完成 / 用户点「重新匹配」
        ↓
内置离线词典（98 部作品的真实 Bangumi 对照，随代码自带）
        ↓ 未命中
本地已学词典（用户手动改过的中文名，优先级最高）
        ↓ 未命中且为外文名
在线 Bangumi 搜索（可配代理，1.5s/3s 短超时，失败整批快速降级）
        ↓
结果当场写入 name_alias / subjects / watched_list / media_files 并立即显示
```

- 数据来源 `app/data/aliases_builtin.json`，随版本库提交，**完全离线也能命中** `Attack on Titan → 进击的巨人`、`Frieren → 葬送的芙莉莲` 等。
- 本机直连 `api.bgm.tv` 实测超时，因此离线词典是主力；在「设置」里填代理后在线源自动生效。
- 带季数的标题优先显示该季中文名（如「更衣人偶坠入爱河 第二季」）；词典未收录该季时只给主标题中文名并标记「主标题匹配」，**不编造季名**，由你在预览里改一次即可永久记住。
- 用户手工修正永远优先于内置词典和在线结果。

### 播放记录与断点续播

- `potplayer.py` 用 Win32 `WM_USER` 消息回读总时长 / 当前位置 / 播放状态（实测有效），无需改 PotPlayer 设置、无需插件。
- `watcher.py` 每 3 秒轮询，按窗口标题切换自动结算会话；进度 ≥90%（可配）自动标记「已看完」。
- 续播用官方 `/seek=hh:mm:ss /current /autoplay` 精确跳转。
- 纠错操作「标记已看 / 标记未看 / 重置进度」只改进度表，**绝不删除观看会话历史**。

## 4. 数据存储

单文件 SQLite（WAL 模式），9 张表。**默认数据目录统一为 `D:\magicvideo`（`library.db` 在根下，封面在 `covers\`，日志在 `logs\`）**；只有 `./start --local` 用项目内 `data/library.db`、`dev.bat` 默认用 `data/dev/library.db` 安全副本。可用 `MAGIC_VIDEO_DATA_DIR` 覆盖。

> **两条独立的数据流**：`watch_progress` / `watch_sessions` 由托盘守护自动累积；`watched_list` 是你手动导入的清单快照，二者没有外键关联。想让已看完的播放记录出现在「看过的列表」，点该页的「从播放记录同步」按钮（幂等、只补 `completed=1`、不改写手动导入的行）。旧版解析器残留的脏标题（如《…》（ 年， ）。- 完）用同页「清洗脏数据」按钮一键修正。
>
> **记录保留**：删除本地视频文件只写 `media_files.deleted_at`，不会删任何一行；观看进度、历史会话与看过的列表继续保留。`watch_sessions` 只能由「历史记录」页的单条人工删除入口删除，没有自动清理逻辑。

| 表 | 用途 |
|---|---|
| `directories` | 已添加的扫描目录与上次扫描时间 |
| `media_files` | 扫描到的文件、文件名解析结果、中文名、季/集 |
| `subjects` | 作品级元数据（Bangumi ID、中文名、原名、季） |
| `watched_list` | 你导入的「看过的列表」 |
| `watchlist` | 追剧清单（标题、已下载/未下载、书写顺序、备注、来源） |
| `watch_progress` | 断点位置、百分比、完成标记、播放次数 |
| `watch_sessions` | 每次观看的起止时间与最远进度 |
| `name_alias` | 中英/中日对照词典（内置 + 用户修正） |
| `settings` | 播放器路径、轮询间隔、阈值、代理、主题、内嵌开关、`embed_hwnd`（内嵌播放器窗口句柄）等 |

`data/` 已被 `.gitignore` 排除，**不会进版本库、不会上传**。旧版本数据库升级只做 `ALTER TABLE ADD COLUMN`，不重建表、不丢已有播放记录。

## 8. 已知限制与后续建议

- 外部打开但尚未加入扫描目录的文件，只有窗口标题作为路径，需先「添加目录」才能续播。
- 在线刮削依赖网络可达性；不通时自动降级到离线词典，未命中的外文名可在导入预览里手动填一次。
- 视频黑名单按「名称包含」匹配（用户明确要求），`jul` / `ipx` / `ure` 这类短英文词可能顺带命中正常片名；发现误伤把它从词表删掉即可，或临时关闭「启用黑名单过滤」后逐个核对。它的作用范围仅限展示层，删文件 / 播放在关闭开关前后行为完全一致。
- 封面抓取依赖站点可达与标题能对上；已改用两个官方搜索 URL + 精确标题优先 + 原始 CDN 直连，常用中文名实测 5/5 精确命中。纯英文/番号文件名仍可能搜不到，此时用卡片上的「设定封面」人工粘贴图片最省事；人工封面不会被后台任务覆盖。没有封面的卡片显示占位图，不影响播放与记录。
- Everything 全盘检索需要 `es.exe` 或 HTTP 服务，两者都没启用时自动降级为媒体库检索。本机官方 `es.exe` 已就位，但 Everything 以 `-svc`（会话 0 服务）运行导致 es.exe 连不上 IPC（Error 8）——需要按软件内提示在 Everything 选项里启用 HTTP 服务并填地址，才能真正走全盘。核心引擎闭源，不能编译进本软件；随包捆绑完整版 `Everything.exe` 属于打包/授权层改动，暂未做。
- 软件内播放依赖 Win32 窗口嵌入，某些播放器皮肤 / 全屏模式可能需要点「重排画面」；任何失败都会自动切回独立窗口。
- 进度表目前以文件路径为主键，移动硬盘换盘后需要重新扫描（重定位向导已列入优化建议）。
- 同类软件调研与 14 条分优先级优化建议见 **`docs/OPTIMIZATION.md`**。
